# Solana Propagation Economics: what faster block propagation is worth to a validator

Live econometric study measuring what faster block propagation is worth to Solana validators: within-leader-window fee/tip slopes, an adoption-saturation model, and a self-updating dashboard at brian.biz/optimum/solana.

## What this is
A port of an Ethereum econometric study ("what is a block-propagation accelerator
like Optimum/mump2p actually worth?") to **Solana**, where the same question is
more alive (Firedancer, DoubleZero, Jito ShredStream all sell propagation speed).
It measures, from live on-chain data, whether a validator that seals a block later
(the time a faster transport would buy it) actually captures more revenue, and
models what a claimed **6× faster transmission** would add per operator. The
guiding principle throughout is intellectual honesty: the study ranks the quality
of its own evidence and states, prominently, that it is a weaker study than the
Ethereum original and exactly why.

## Data collection (live, can't be backfilled)
Three collectors run continuously on a **Frankfurt** node against a **Yellowstone
Geyser gRPC** feed (HelloMoon), reboot-persistent, with a 48h rolling window:
- **Sentry**: slot-status stream (`FIRST_SHRED_RECEIVED` → `COMPLETED`), giving a
  per-slot propagation window and skip/dead-fork detection.
- **Jito tips**: summed from balance deltas on the 8 tip accounts.
- **Leader fees**: block-meta `Fee` reward (priority + base, post-SIMD-0096).

Operators are clustered from every staked validator by shared vote-withdrawer or
website (union-find). The panel is one row per leader slot, joined to the leader
schedule; steady state ≈ 432,000 slots / 48h / ~700 leaders.

## Identification & method
- **Within-leader-window design**: compare a leader's own 4 consecutive slots, so
  stake/hardware/geography/near-term load are held fixed; the running variable is
  sealing lateness: completion beyond the position-implied schedule.
- **Inference**: hand-rolled CR1 cluster-robust SEs + restricted wild cluster
  bootstrap (Rademacher), plus **two-way (leader × hour) CGM clustering**, all
  cross-validated against `statsmodels` to machine precision in the test suite.
- **Pre-registered rule, applied in code**: "a slope indistinguishable from zero
  prices at zero." A channel failing the wild-bootstrap p<0.05 contributes $0 to
  every figure.

## Key findings (48h panel)
- **Leader fees respond to delay**: sealing slope +0.00336 SOL/100ms,
  **t 6.24, wild-p <0.0001**, and it survives two-way clustering (t 6.00, SE
  inflation 1.04×, 49 hour-clusters).
- **Jito tips do not**: +0.00010, t 0.60, **wild-p 0.575**. The tips channel got
  weaker with more data, and the pre-registered rule zeroed it automatically;
  a cross-operator test agrees (faster operators do not earn more tips).
- **Position placebo fires negative** (t −3.05): backlog-drain across the leader
  handoff; it's differenced out by construction, which is why the design
  residualizes on position.
- **Skip rate ≈ 0.21%** over two days (an early one-day 2.08% was a single noisy
  window); dead-fork hazard still underpowered (~57 events and growing).

## The counterfactual (all free parameters exposed as sliders)
`u(α) = u_max · min(1, α/θ) · [φ + (1−φ)(1−α)]`, priced at live SOL (~$75):
- **κ (compressible share, default 25%)**: the observed window is mostly the
  leader's own shred-emission span, not compressible transit; every dollar scales
  linearly in κ, and κ is unidentified from one vantage point.
- **Cannibalization (1−α)**: the delay gain is pulled from the next slot, so
  per-operator figures are lone-adopter bounds and the total is not additive.
- **θ (peer ramp, ~67%)**: an RLNC overlay only helps stake that is able to
  receive on it, and a Solana block needs 2/3 to root → a bootstrap trap where
  the first mover earns almost nothing.
- **φ (net-new share, ~0)**: sets the saturation floor; near zero for pure
  delay, so the durable value is largely a public good.

## Honest limitations (stated on the page, first)
Demand simultaneity makes the slope an **upper bound** (a downgrade from
Ethereum's measured relay bid curve); κ is unidentified at one vantage point;
Timely Vote Credits (the inflation channel latency actually moves) are unmeasured;
the skip hazard is assumed, not priced. More data sharpens precision, not
identification.

## Deliverables
- Live, self-updating page: **https://brian.biz/optimum/solana** (served by a
  FastAPI "watcher"; regenerated by a daily 06:00 job that fetches live SOL price,
  runs the bootstrap, and re-renders; headline numbers are server-side rendered so
  the page is legible without JavaScript).
- Reproducible pipeline (`run_solana.py` → `revenue_graph.json` → page), operator
  grouping (`find_groups.py`), and a library-cross-checked test suite
  (`tests/test_estimators_vs_libraries.py`).

## Stack
Python (numpy/pandas), hand-rolled econometrics validated against
statsmodels/scipy; Yellowstone Geyser gRPC; DuckDB (Ethereum side only); vanilla
HTML/SVG dashboard, no frameworks.
